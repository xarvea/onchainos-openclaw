# ADR Log — MICOW

Catatan keputusan arsitektur (Architecture Decision Records).
Format: Status / Konteks / Keputusan / Alternatif / Konsekuensi.

---

## ADR-0001 — Chain: Solana

**Status:** Accepted
**Konteks:** Perlu chain dengan biaya transaksi rendah, finality cepat, ekosistem
NFT matang, dan dukungan standar terbuka (Metaplex).
**Keputusan:** Solana (mainnet-beta), mulai dari devnet untuk pengembangan.
**Alternatif:** Ethereum L2 (biaya lebih tinggi, ekosistem NFT kuat tapi gas mahal
untuk mint massal), Base (emerging).
**Konsekuensi:** Terikat ekosistem Solana; leverage Metaplex Core/Candy Machine;
indexer pakai DAS.

---

## ADR-0002 — NFT Standard: Metaplex Core (bukan Token Metadata)

**Status:** Accepted
**Konteks:** Proyek greenfield tanpa kebutuhan kompatibilitas legacy.
**Keputusan:** Pakai **Metaplex Core** sebagai standar utama.
**Alternatif:** Token Metadata (legacy, biaya lebih tinggi, tanpa plugins).
**Konsekuensi:** Mint ~80% lebih murah, royalty via plugin. Perlu verifikasi
dukungan marketplace pihak ketiga untuk Core (semakin luas).

---

## ADR-0003 — Indexer: Helius DAS + Webhooks (bukan custom Geyser sejak awal)

**Status:** Accepted (dengan abstraksi)
**Konteks:** Tim kecil, ingin ship cepat; custom Geyser butuh minggu–bulan +
operasional berat (reorg handling, backfill, parsing IDL).
**Keputusan:** MVP pakai **Helius DAS + Webhooks**, cache di Postgres. Bungkus
dalam interface `IndexerProvider` agar bisa swap ke custom Geyser nanti.
**Alternatif:** Custom Geyser indexer dari hari pertama.
**Konsekuensi:** Vendor lock ringan (mitigasi: abstraksi). Query kompleks
(filter listing by price/rarity) dilakukan di Postgres sendiri.

---

## ADR-0004 — Frontend: Next.js App Router

**Status:** Accepted
**Konteks:** Marketplace publik butuh SEO, OG preview sosial, Core Web Vitals.
**Keputusan:** Next.js 15 App Router (RSC + ISR).
**Alternatif:** Vite React SPA (buruk untuk SEO tanpa pre-render manual).
**Konsekuensi:** Server Components untuk read-heavy pages; Client Components
hanya untuk interaksi wallet.

---

## ADR-0005 — Escrow: Auction House dulu, custom kemudian

**Status:** Proposed (perlu keputusan — lihat D1 di BLUEPRINT)
**Konteks:** Perlu escrow on-chain untuk listing fixed-price yang aman.
**Keputusan usulan:** Pakai **Metaplex Auction House** (standar, teruji) untuk MVP;
tulis program Anchor custom hanya jika butuh fitur yang tak didukung.
**Alternatif:** Program Anchor custom sejak awal (kontrol penuh, tapi audit mahal).
**Konsekuensi:** Lebih cepat & aman; fleksibilitas terbatas pada fitur AH.

---

## ADR-0006 — ORM: Drizzle (bukan Prisma)

**Status:** Accepted
**Konteks:** Stack TS modern, kemungkinan edge runtime, query SQL-heavy untuk indexer.
**Keputusan:** Drizzle ORM + drizzle-kit.
**Alternatif:** Prisma (DX enak, tapi lebih berat untuk edge, engine overhead).
**Konsekuensi:** SQL-first, cold-start rendah, cocok Next.js edge.

---

## ADR-0007 — Monorepo: pnpm workspaces + Turborepo

**Status:** Accepted
**Konteks:** Multi-app (web, worker) + paket bersama (domain, db, solana, ui).
**Keputusan:** pnpm workspaces + Turborepo.
**Alternatif:** Nx (overkill untuk MVP), Bun workspaces (ekosistem Solana/Next
belum sepenuhnya aman).
**Konsekuensi:** Caching task, reuse kode, struktur jelas.
